## [0.5.0] - 2026-08-07

### Добавлено
- Страница «Прайс» устанавливается на домашний экран отдельным значком —
  свой `static/fav/price.webmanifest` («Прайс»), не общий `site.webmanifest`
  (см. ARCHITECTURE.md, «PWA»)
- Кнопка «Установить на экран» (`static/js/install.js`) — Android/desktop
  Chrome/Edge через `beforeinstallprompt`, iOS — текстовая подсказка
  вместо кнопки (Apple не позволяет запускать установку программно)
- `apple-mobile-web-app-capable`/`apple-mobile-web-app-title` на всех
  страницах — на iOS Safari «Добавить на экран» теперь открывает
  полноэкранный standalone-режим с правильным названием под иконкой,
  а не закладку с именем сайта по умолчанию

### Изменено
- `site.webmanifest` — `name`/`short_name` переименованы в «Очередь»
  (было «Carpool Queue — Очередь заказов» / `"Carpool"`), добавлено
  явное поле `id`

## [0.4.2] - 2026-08-07

### Изменено
- `static/sw.js` — стратегия кэширования статики поменяна с cache-first на stale-while-revalidate: закэшированный файл отдаётся сразу, но всегда параллельно обновляется из сети. Cache-first требовал вручную бампать версию кэша при каждом изменении `style.css`/`*.js`, из-за чего пользователь застрял на старой версии `session.js` после фикса 0.4.1, пока не сделал жёсткую перезагрузку — теперь версия подхватывается сама, максимум одна лишняя загрузка

## [0.4.1] - 2026-08-07

### Исправлено
- `static/js/session.js` не передавал роли (`is_driver`/`is_dispatcher`/`is_admin`) во фронтенд-объект текущего пользователя, хотя `GET /me` их уже отдавал — из-за этого пункт «Админ» не появлялся в навигации, страница «Админ» показывала «Доступ только для администратора» даже реальному администратору, а кнопка «Назначить» не появлялась у диспетчера на дэшборде. Найдено сразу после деплоя 0.4.0 при реальной проверке на проде

## [0.4.0] - 2026-08-07

### Добавлено
- Роли пользователей — водитель/диспетчер/администратор, совмещение возможно (`User.is_driver`/`is_dispatcher`/`is_admin`, см. ARCHITECTURE.md, «Роли и права доступа»)
- Прямое назначение и переназначение заказа диспетчером вне очереди (`POST /orders/{id}/assign`) — назначает только водителей из очереди этого типа, при переназначении прежний исполнитель возвращается вторым в очередь
- Диспетчер и администратор теперь могут отменить любой заказ, не только созданный/назначенный себе
- Admin-only API управления пользователями/ролями/очередью: `POST /admin/users`, `PATCH /admin/users/{id}/roles`, `POST`/`DELETE /admin/users/{id}/queue/{type}`, `POST /admin/queue/{type}/reorder` — веб-аналог `scripts/add_user.py`/`scripts/reorder_queue.py`
- Страница «Пользователи» — список всех с ролями рядом с именем, видна любому залогиненному
- Страница «Админ» — добавление пользователей, управление ролями, порядок очереди (кнопки вверх/вниз); доступна только администраторам, пункт в навигации виден только им
- Дэшборд: у диспетчера/администратора на заказах появляется контрол «Назначить»/«Переназначить», новая секция «Все активные заказы»
- `scripts/grant_role.py` — точечная выдача/снятие одной роли по username (в т.ч. для выдачи первой роли администратора после деплоя)
- PWA: `static/sw.js` кэширует только статику (css/js/иконки), данные всегда приходят по сети — сайт можно установить на домашний экран телефона

### Изменено
- `scripts/add_user.py` — теперь проставляет роль (`is_driver` по умолчанию, `is_dispatcher` с флагом `--no-queue`)
- `GET /me`/`GET /users` — отдают роли пользователя
- `/respond`, `/self-assign`, `/complete` теперь дополнительно требуют роль водителя (было — только идентичность из сессии)
- Заголовки вкладки браузера (`<title>`) на всех страницах — только название страницы, без префикса «Carpool Queue» (см. STYLEGUIDE.md)
- `site.webmanifest` дополнен `scope`/`lang`/`description`

## [0.3.0] - 2026-08-03

### Добавлено
- Вход через VK ID (OAuth) — серверная сессия вместо ручного выбора себя из списка в шапке, самопривязка VK-аккаунта к пользователю при первом входе (см. PROGRESS.md, Шаг 25; ARCHITECTURE.md, «Вход через VK ID»)
- Адаптивный favicon (иконки нескольких размеров, `apple-touch-icon`, `site.webmanifest`) взамен одиночного файла — браузер/ОС сами выбирают нужный размер под устройство

### Изменено
- Прод перенесён на новый VPS (тот же домен `zakaz.glorden.ru`), старый сервер выведен из эксплуатации (см. PROGRESS.md, Шаг 24)
- `/respond`, `/self-assign`, `/complete`, `/cancel` и `POST/PUT/DELETE /price` теперь реально проверяют личность вызывающего по сессии вместо `user_id` из тела запроса — принимают/отклоняют/завершают/отменяют заказ и правят прайс только от своего имени (см. PROGRESS.md, Шаг 26; ARCHITECTURE.md, «Технический долг»). Ломает старый контракт: `user_id` в телах этих запросов больше не принимается
- Сайт закрыт под VK ID целиком: `GET`-эндпоинты списков (`/users`, `/queue`, `/orders`, `/orders/pending`, `/price`, `/price/log`, `/activity`, `/statistics/summary`) и `/docs`/`/redoc`/`/openapi.json` теперь тоже требуют сессию, не только мутирующие; страницы «Прайс»/«История заказов»/«Журнал действий»/«Статистика» без сессии показывают только приглашение войти, как и дэшборд (см. PROGRESS.md, Шаг 27; ARCHITECTURE.md, «Технический долг — закрыт (Шаг 27)»)
- HTTP Basic Auth на Caddy убран целиком — VK-сессия единственная защита сайта (см. DEPLOY.md)

### Удалено
- Мёртвое поле `User.password_hash` — никогда не проверялось, вход теперь только через VK ID

## [0.2.0] - 2026-07-23

### Добавлено
- Деплой на VPS (Ubuntu + Caddy + systemd), `zakaz.glorden.ru` (см. DEPLOY.md)
- HTTP Basic Auth (Caddy) на весь сайт, включая API
- Страница «Прайс»: редактируемый прайс-лист, поиск, лог изменений
- Единая навигация между страницами (`nav.js`), `STYLEGUIDE.md`, мобильная адаптация
- Отмена заказа (`POST /orders/{id}/cancel`)
- VK-уведомления о предложенном заказе, с тегом водителя и ссылкой на сайт
- Предупреждение в форме создания заказа, если маршрут набран латиницей
- Первые автотесты: `tests/test_queue_logic.py` — арифметика очереди (принятие/отказ/отмена)
- Журнал действий (`GET /activity`, страница «Журнал действий») — отдельная от истории заказов хронология событий: создание, предложение, принятие, отказ, завершение, отмена заказа и изменения очереди
- Самоназначение на заказ вне очереди (`POST /orders/{id}/self-assign`) — кнопка «Самоназначиться» на дэшборде, обязательная причина, сохраняется в истории заказа и журнале действий, водитель уходит в конец очереди как при обычном принятии
- Скрипт `scripts/reorder_queue.py` — ручная перестановка порядка в очереди (для редких случаев), по образцу `scripts/add_user.py`
- Страница «Статистика» (`GET /statistics/summary`) — общие счётчики по заказам (всего/завершено/активно/отменено) и разбивка по водителям (получено/завершено/отменено)
- Вторая, независимая очередь для коротких поездок (наряду с дальними) — тип заказа обязателен при создании (радиокнопки, без значения по умолчанию), дэшборд показывает обе очереди отдельными блоками, история заказов — с фильтром по типу, `scripts/add_user.py`/`scripts/reorder_queue.py` работают с обеими очередями

### Изменено
- Текст сообщения о самоназначении (VK-уведомление и журнал действий) переформулирован без личного глагола прошедшего времени («самоназначился») — согласование по мужскому роду было некорректным для водителей-женщин
- Текст VK-уведомления о предложенном заказе: добавлена доп. инфа из комментария, переформулировано на несколько строк
- VK-уведомление при отказе теперь называет, кто отказался, перед тем как предложить заказ следующему в очереди
- Добавлено отдельное VK-уведомление о том, что заказ принят конкретным водителем

### Исправлено
- Вёрстка кнопок «Принять»/«Отклонить»/«Завершить» на дэшборде
- `/cancel` возвращал водителя первым в очереди вместо второго
- XSS на странице истории заказов (небезопасный `innerHTML`)
- Мёртвый статус `unassigned` убран из модели и документации
- Убрано отображение сырой позиции `(позиция N)` в очереди на дэшборде
- `POST /orders`, `PUT /price/{id}` и `POST /price` возвращали пустой объект `{}` вместо созданной/изменённой записи (коммит записи в лог инвалидировал уже загруженный объект без повторного `refresh`)
- «Статистика по водителям» задваивала водителя, состоящего в обеих очередях, с одинаковыми числами
